# Security Policy

## Supported versions

KMJ Forge is currently in early development. Security fixes are applied to the latest `main` branch and the latest published release where practical.

## Reporting a vulnerability

Please do **not** open a public GitHub issue for an undisclosed vulnerability.

Use GitHub's private vulnerability reporting feature when enabled for this repository. If that is unavailable, contact the project maintainers privately through KMJ TECHNO's official contact channel.

Include:

- affected version or commit;
- reproduction steps;
- impact;
- proof-of-concept when safe;
- suggested mitigation if known.

## Security principles

KMJ Forge follows:

- least privilege;
- restricted execution by default;
- secret isolation;
- explicit approval for destructive/high-risk actions;
- no silent force-push/reset/destructive cleanup;
- repository content is treated as untrusted input;
- verification before completion.

## Disclosure

Please allow maintainers reasonable time to investigate and release a fix before public disclosure.
