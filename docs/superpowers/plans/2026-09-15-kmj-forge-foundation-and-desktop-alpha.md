# KMJ Forge Foundation and Desktop Alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the verified KMJ Forge v0.1.0 baseline, protect `main`, freeze Phase-00 contracts, then deliver a testable Forge Desktop Alpha vertical slice using the same headless engine.

**Architecture:** Python owns the Forge engine and versioned contracts. Tauri 2 + React + TypeScript provides the desktop shell. Provider/model integrations are adapters behind a dynamic capability registry; context is compiled from repository evidence rather than dumped wholesale.

**Tech Stack:** Python 3.11+, JSON Schema, SQLite, Git/GitHub, Tauri 2, Rust, React, TypeScript, Vite, Vitest, Playwright where practical.

**Spec:** `docs/superpowers/specs/2026-09-15-kmj-forge-foundation-and-desktop-alpha-design.md`

## Global Constraints
- Project is only `KMJ Forge`; no product-specific KMJ code.
- Canonical repository: `kmjtechno/kmj-forge`, PUBLIC, Apache-2.0.
- Initial implementation version: `0.1.0`; roadmap version: `2.0`.
- `FREE_ONLY` never falls back to paid inference.
- Main remains stable; normal work is PR-based.
- Never force-push, destroy user work, or weaken verification/security.
- No completion claim without fresh executable evidence.

## Execution order
Tasks 1-2 are the publication gate and must finish first.
Task 3 freezes shared contracts before Tasks 4-7 can expand safely.
Tasks 4 and 5 may proceed independently after Task 3, then integrate into Task 6.
Task 7 consumes the stable engine interfaces from Tasks 3 and 6.
Task 8 is the alpha completion gate.

## Rollback
Every development task uses a feature/fix branch or isolated worktree.
Before risky changes Forge records a Git checkpoint and affected files.
A failing PR is fixed on its branch or abandoned; `main` is never force-reset.
Desktop/provider experiments may be removed without changing stable protocol contracts.

## Completion report
For every completed task report: commit/PR, files changed, exact commands, test counts, CI/CodeQL status, security findings, benchmark deltas where relevant, known limitations, and next action.
